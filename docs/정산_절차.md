# 사후 정산 절차

기획안 7번(사후 정산)을 [교환권 정산 도구](../voucher-settlement/index.html)의 각 탭과 연결한 실행 절차입니다.

## 집계 단위 — 조 단위 (확정)

정산은 **부스가 아니라 조 단위**로 집계합니다 ([운영 역할](운영_역할.md) 참고). 조와 부스가 1:1이 아닌 곳이 있어 마감 방식이 달라집니다.

| 조 | 부스 | 마감 방식 |
|---|---|---|
| 5조 | 2개 (떡볶이·오뎅·순대 / 샌드위치) | 두 부스 교환권을 합쳐 5조 몫으로 제출 |
| 9조 | 2개 (의류 판매대 / 의류 2) | 두 부스 교환권을 합쳐 9조 몫으로 제출 |
| 7 · 8 · 11조 | 1개 공유 (젓갈·새우젓) | 한 부스 안에서 각자 따로 계수해 조별로 제출 |
| 그 외 | 1개씩 | 그대로 제출 |

> **7·8·11조는 교환권함을 각자 따로 두어야 합니다.** 세 조가 한 천막에서 파는데 교환권이 한 통에 섞이면 조별 매출을 되돌릴 수 없고, 초기 지급액을 뺄 수도 없어 대사가 깨집니다. 개장 전 플로트 배분부터 세 조로 나눠 기록하세요.

## 사전 준비 (개장 전)
1. [부스 관리] 탭에 **조를 단위로** 등록 (예: "1조 국수", "7조 새우젓", "5조 떡볶이·샌드위치"). 도구의 "부스"는 자유 입력 이름이므로 조 이름을 그대로 쓰면 됩니다.
2. [초기 지급(플로트)] 탭에 **조별로** 나눠준 잔돈용 교환권 수량을 권종별로 입력. 5조·9조는 두 부스에 나눠 주더라도 합계를 조 몫으로 입력하고, 7·8·11조는 각각 따로 입력합니다.

## 마감 시 (판매 종료 직후)
3. 각 조는 보유 중인 교환권을 권종별로 계수하여 정산조에 제출 (5조·9조는 두 부스분을 합쳐서, 7·8·11조는 각자 따로)
4. 정산조는 [마감 정산 제출] 탭에 **조별** 제출 수량을 입력
5. 교환권 부스는 하루 동안의 현금 판매액, 계좌이체 판매액, 발행한 교환권 총 수량(권종별)을 집계하여 [교환권 부스] 탭에 입력

## 대사(검증)
6. [대사 리포트] 탭에서 아래 세 가지를 확인:
   - **조별 매출**: 제출 보유액 − 초기 지급액 (기획안 7-1: 매출 검증)
   - **교환권 부스 대사**: 발행액 중 실제 판매분(발행액 − 초기 지급액 합계) vs 실제 판매 수령액(현금+계좌이체) (기획안 7-2)
   - **전체 요약**: 조별 매출 합계와 교환권 부스 실수령액 비교
7. 차이가 발생하면 다음을 확인:
   - 조의 교환권 계수 오류 또는 누락
   - 초기 지급 수량 기록 누락
   - 7·8·11조의 교환권이 서로 섞였는지 (한 부스를 공유하므로 가장 먼저 의심할 지점)
   - 5조·9조가 두 부스 중 한쪽 교환권을 빠뜨렸는지
   - 교환권 부스의 발행 수량 기록 누락
   - 고객이 사용하지 않고 가져간 교환권 (미회수분)

## 수익금 확정 및 보고
8. 대사 완료 후 최종 수익금(교환권 부스 실수령액 기준)을 확정
9. 수익금 사용 내역(구제 헌금, 선교 기금 등)을 사전 공지된 사용처에 따라 집행하고 보고 `(확정 필요: 보고 방식 및 시기)`

> **사전 구매 신청분 주의**: [사전 구매 신청](사전_구매_신청.md)을 선결제(계좌이체)로 받기로 정하면, 그 매출은 교환권을 거치지 않으므로 위 대사에 잡히지 않습니다. 이 경우 선결제 내역을 별도로 집계해 8번의 최종 수익금에 합산해야 합니다. 당일 교환권 결제로 정하면 위 절차를 그대로 쓰면 됩니다.

## 데이터 백업
- 정산 도구의 [데이터 관리] 탭에서 작업 중간중간 JSON 내보내기로 백업을 받아둘 것 (브라우저 데이터이므로 기기/브라우저 초기화 시 유실 위험)
- 최종 리포트는 CSV로 내보내 별도 보관
